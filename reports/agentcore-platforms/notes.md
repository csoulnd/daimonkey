# 从定义理解 AgentCore · 讲稿

## 开场
两个产品都是平台，不能与某个 Agent、模型或 SDK 混为一谈。本次沿用知识库证据基线，未进行部署实测。

## 阿里云
从构建和治理的定义进入，讲清托管 Harness、高代码部署、本地纳管三种入口。接着切换到真实控制台，沿工作空间与 Agent 列表、创建配置、资产绑定、会话结果展示实际操作。每个动作说明对应能力和模式边界。最后讲 Workspace、Agent、实例、Session 的职责，以及平台托管不能直接保证业务幂等与任务恢复。

## Amazon
先定义可组合的构建与运行平台。初始七项服务是模块，七维韧性架构模型是完整系统的分析维度，两者不同。按五步追踪 Runtime 上的一次调用，强调托管 Harness 与用户代码是两条执行入口；工具和记忆服务按需选择，安全和观测横向参与。最后说明运行托管与企业应用责任的分工。

## 收尾
阿里云以平台资源与实际操作为理解入口，AWS 以执行责任与可组合服务为理解入口。不要从公开资料推导两家内部技术栈或性能优劣。
