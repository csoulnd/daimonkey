## 章节边界

- 模型家族概览位于模型结构之后、推理基础之前，只介绍代表型号、总参数/激活参数、Dense/MoE、注意力类型和关键配置；按具体版本提供官方模型卡/config/技术报告，不把整个家族视为同一种结构。不展开架构推导、显存核算、性能优化或完整训练史；总览横向对照，各家族使用统一简短模板。

- 数学知识必须呈现：线性代数与张量形状支撑模型计算，概率支撑 softmax/采样，信息论支撑分布差异与精度评测；以推理需要为界，不扩写成完整数学教材。
- 导读只建立全景。`request-lifecycle` 保留 slug，内容聚焦前向计算到 Prefill/Decode/采样的通用生成过程；框架内的排队、缓存分配、Worker 与执行器调用留给 `framework-lifecycle`。
- KV Cache：模型卷讲结构影响，推理基础讲形状和容量，算子卷讲访问与计算，系统卷讲分配、复用和回收。
- 量化：基础卷讲数值表示，算子卷讲计算实现，系统卷讲精度/内存/性能取舍。
- 长上下文：模型卷讲位置与结构机制，系统卷讲调度、缓存与服务代价。
- mRoPE cache、MegaMoE 等必须绑定具体实现与版本，作为通用机制的进阶案例。

## 写作顺序

1. 先补线性代数、张量与概率等必要基础，以及软硬件栈的简明定位。
2. 写模型结构的最小链路：tokenizer → embedding → attention → FFN/Norm → 输出与采样所需概念。
3. 模型结构之后先写模型家族概览，以代表型号、参数规模和常见结构连接真实模型；随后写推理基础三篇，形成从生成过程到计算、显存代价的闭环。
4. 算子与系统按问题成组展开，例如 attention → FA/PA → KV 管理；每组穿插可复现的实践。
5. 最后用具体框架的请求路径串起调度、缓存、通信与执行，不重复基础卷的生成原理。

### tensor-layout · 张量基础：形状、布局与数据类型

- 所属卷：数学与计算基础，承接 linear-algebra。
- 状态：v0.1 已发布到公开内容目录，`series.yaml` 已移除 planned。
- 正文路径：`content/learn/inference/tensor-layout.md`；写作记录保留在 `docs/drafts/learn/tensor-layout.md`（与发布版逐字一致）。
- 本篇目标：读懂张量各轴含义，推导常见运算的形状，并区分逻辑形状、底层存储与数据类型。
- 架构：①从 token 表示 [B,S,D] 建立问题；②张量、阶数、shape 与轴语义；③索引、切片及维度增减；④逐元素运算、广播、归约与批量矩阵乘法；⑤reshape 与轴置换的区别；⑥storage、stride、offset、连续性及视图/拷贝；⑦dtype、类型转换与逻辑存储字节数；⑧贯穿示例、最小实验与自测。
- 范围边界：以普通稠密 strided 张量为主；dtype 仅介绍用途、字节数与转换，位编码/舍入/数值范围留 numeric-formats；不展开完整 Attention、GPU 分块布局、量化实现与性能调优。
- 已完成：八节正文、参考与修订、八道自测及答案；按 [B,S,D] → [B,S,H,d] → [B,H,S,d] 贯穿，补广播语义误用、reshape/转置对照、stride 与 offset 手算、视图/连续化及逻辑字节数边界。
- 验证：草稿七段 Python 代码各自在独立命名空间执行、断言全部通过；站点 `_render_markdown` 检查目录、六张表格、七段代码及 stride 公式文本；`git diff --check` 通过；构建不新增依赖（未引入 torch）。
- 待确认：作者评审 v0.1 的布局深度、例子与篇幅；示例在 Python 3.12.14 / PyTorch 2.14.1 CPU 临时环境运行，未测 GPU 或性能。
