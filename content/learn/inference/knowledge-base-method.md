# 知识库核心思路

> 围绕“模型如何执行、瓶颈如何形成、优化如何验证”组织知识。学习篇建立连续理解，专题笔记提供可查阅的答案，实验记录保留证据，让结论能够被解释、复现和修正。

## 以问题串起知识

一条完整的学习链应当连接：**遇到的问题 → 数学与模型机制 → 算子和系统实现 → 实验验证 → 适用边界**。

例如“长输入为什么更占显存”：先理解 Attention 及 KV Cache 的形状，再按层数、KV head、序列长度与数据类型估算缓存开销，最后结合框架的分配策略测量实际占用。公式估算与实测不一致时，应检查权重、临时张量、预分配和并行切分等条件，而不是直接把差异归因于公式失效。

数学知识承担解释机制的作用，源码说明具体实现，实验检验结论在当前环境下是否成立。三者需要相互连接。

## 三类内容，各有职责

| 内容 | 回答的问题 | 应当保留什么 |
|---|---|---|
| 学习篇 | 为什么如此，怎样连接前后知识 | 问题背景、前置知识、推导与工程对照 |
| 专题笔记（原子笔记） | 某个概念或结论是什么，何时适用 | 独立可读的解释、公式符号、边界、来源与关联文章 |
| 实验记录 | 在什么条件下观察到了什么 | 模型与软硬件版本、输入负载、命令、指标、结果与局限 |

学习篇位于公开的[推理基础频道](/learn)；专题笔记与实验记录逐步沉淀到登录后的[个人知识库](/knowledge)。原子笔记以一个可回答的问题为单位，必要时保留完整例子，不把知识拆成脱离上下文的碎片。

允许专题笔记复述学习篇的核心结论，以便独立阅读；但应链接原文及适用版本。内容的一致性依靠来源与修订关系维护。

## 先理解机制，再比较实现

课程先呈现必要的数学与计算基础，再讲模型结构、生成过程和代价；模型家族用于对照结构差异，算子与系统章节说明优化如何落地，实践章节检验理解。

同一主题可以跨卷出现，但每次回答不同的问题。以 KV Cache 为例：推理基础解释缓存内容与容量，模型结构解释注意力变体的影响，算子章节解释访存方式，系统章节解释分配、复用与回收。后文引用前文定义，避免反复建立不同口径。

通用原理与具体实现分别说明。以某个框架、芯片或模型为例时，标注版本；特殊实现的行为不能直接推广成所有平台都成立的规律。

## 让结论可查证

- **先说清问题与结论**：读者应知道本篇解决什么、需要哪些前置知识。
- **按解释需要选形式**：结构用图，比较用表，数量关系用公式，执行行为用代码或实验；不要求每篇都具备所有形式。
- **给出条件**：公式说明符号、单位与假设；性能结论说明输入长度、输出长度、并发、精度格式及统计口径。
- **标明证据来源**：区分官方说明、理论推导、本地实测和待验证判断；实现类引用尽量固定到版本或 commit。
- **提供检验方式**：按主题安排自测问题或最小实验，让读者能检查理解。

例如“某优化提升吞吐”必须说明与什么基线比较、测试负载是什么、延迟和精度是否变化。实验记录保存原始结果，学习篇提炼机制，专题笔记总结适用边界。

## 修订与归档

站点仓库中的学习篇是公开文章的主版本。完整文章的单向归档用于保留历史；从文章提炼的专题笔记用于检索与复用，两者分别维护。

文章修订后，检查关联笔记及实验结论是否仍然适用；失效结论注明原因和替代内容。自动归档仍在规划中，当前通过人工维护引用与修订记录，不能把规划中的流程当作已经实现的能力。

网站仓库、知识库仓库与联系方式见[导读](/learn/inference/introduction)。
