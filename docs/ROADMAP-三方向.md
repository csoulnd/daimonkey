# 三方向划分:Harnes / FM / NV(需求澄清稿)

> 定位:本文是**交接与需求澄清**,不是实现方案。三个方向的需求由需求方(产品视角)确认后,
> 再按 AGENTS.md 流程立专家、进 PLAN.md 开发。

## 方向定义与现有资产映射

| 方向 | 含义 | 站内现状 | 缺口 |
|---|---|---|---|
| **智能体(Harness)** | Agent 运行时/编码智能体/框架生态 | 现有热度榜各赛道(Agent Harness/开源框架/通用/Claw/国产)即此方向数据 | ①各赛道是否收拢为统一「Harness 频道」;②是否引入能力评测维度(如 SWE-bench、AgentBoard 类基准),当前只有生态热度 |
| **模型(FM)** | 模型评测与对比 | 模型评测榜已上线(SuperCLUE 月报+AI 复评) | ①海外基准聚合(AA Index/Podium,**卡在 AA API key**);②LMArena Elo(卡网络通道);③更多基准列与历史趋势 |
| **硬件(NV)** | 推理硬件(以 NVIDIA 为主) | **空白,全新方向** | 需求待澄清,见下 |

**横切层(不专属任何方向)**:AI 资讯(可按三方向重新分类打标)、门户主页(可改三方向入口)、个人工作台、智能助手。

## 待需求方确认的问题(按优先级)

### 方向级
1. 门户信息架构是否调整为三方向一级入口(Harness/FM/NV 各一个频道页,热度榜/模型榜成为频道内的榜)?
2. AI 资讯是否按三方向重新分类(现七分类保留为二级标签)?

### NV 方向(最需要输入)
3. 内容形态是什么?候选:a) GPU/加速卡规格与性价比榜;b) 推理服务性价比(FM×NV 交叉:tokens/元/延迟);c) MLPerf 类公开基准榜;d) 行业动态聚合。
4. 数据源预期?公开可溯源源(NVIDIA 官方规格页、MLPerf 结果库、云厂商定价页)是否满足"每数字可溯源"的站规?
5. 与需求方的推理基础设施背景(知识库 infra 部分)如何联动——是否作为该方向的专家知识底座?

### FM 方向
6. AA API key 是否去注册(解锁 Podium/AA Index/海外基准全量)?LMArena 是否提供代理通道?
7. 模型历史趋势(多期月报曲线)是否要上?

### Harness 方向
8. 各赛道收拢后,现有联合榜保留还是被 Harness 频道替代?
9. 是否引入能力评测数据源(SWE-bench 等公开榜),与生态热度并行展示?

## 交接要点(实现侧已知事实)

- 架构现状:静态站(templates+sitegen)+serve.py(防护/账号/看门狗)+PIAgent 助手;新增方向=registry 配置+源模块+榜单页模板复用,模型榜(SuperCLUE 链路)是最佳参照实现。
- 数据通道实测结论见 `skills/model-eval`(AA 需 key、LMArena 断连、SuperCLUE PDF 链路可用);NV 方向数据源**尚未做过可达性探测**,立项前应先跑一轮 spike。
- 所有新功能走:AGENTS.md 专家流程 → PLAN.md 排期 → 实现 → 沉淀回专家。
