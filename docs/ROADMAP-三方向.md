# 三方向划分:Harness / FM / NV(需求澄清稿)

> 定位:**交接与需求澄清**,非实现方案。结论由需求方逐轮确认,回填本文;
> 全部冻结后再走 AGENTS.md 流程立专家、进 PLAN.md 开发。

## 已确认的结论(2026-10-17 第二轮)

1. **三方向划分确认**:智能体(Harness)/ 模型(FM)/ 硬件(NV)。
2. **热度榜可信度问题定性**:现有按赛道组织的收录方式不合理——协议(MCP)、编排工具(n8n)等
   非智能体产品混入榜单。**收录前必须严格甄别;组织方式改为从产品维度出发**。新收录口径待定(见问题 1)。
3. **FM 数据源决策**:以 https://artificialanalysis.ai/ 为主要参考,**取其部分数据、页面标注来源即可**。
   (实现侧备注:AA 站点为 SPA 且本机访问慢,优先官方 API(免费 key);直接爬取需先 spike 其数据端点与频控。)
4. **NV 方向**:先做**空页面占位**,内容逐步添加。
5. **统一组织形式(探索中,不写死)**:每个方向都想有 **新闻 / 榜单 / 每周总结** 三件套。
   实现原则记为:信息架构**频道化且配置驱动**(registry 定义方向与板块),页面结构不硬编码,
   组织形式随讨论演进可调。

## 待确认问题(当前轮)

### 1. Harness 榜收录甄别标准(最高优先)
产品维度出发的候选口径,请挑或改:
- **A. 仅"能自主干活的产品"入核心榜**:面向用户可用、具备自主执行/多步编排能力(编码智能体、
  通用助手、Claw 类);协议(MCP)、库/框架(LangChain)、编排工具(n8n)一律不入核心榜。
- **B. 核心榜 + 生态榜分层**:A 的口径做核心榜;协议/框架/工具另设"生态榜"平行展示,不与产品混排。
- **C. 按产品形态分组**:助手/编码/编排/协议各一组,组内排名,不做跨组总榜(现联合榜取消)。
- 顺带定:**现有联合榜**在新口径下的去留。

### 2. AA 取数范围
intelligence index / 各基准分 / 价格 / 吞吐延迟,先要哪些列?更新频率跟随 AA 日更还是降频?

### 3. 频道化信息架构
门户改为三方向频道入口(Harness/FM/NV 各频道页内含 新闻+榜单+周总结)?现有导航(热度榜单/AI 新闻)如何过渡?

### 4. 每周总结形态
AI 自动生成(现周报管线可复用)为主、人工可编辑?还是纯人工?发布前是否需要审核态。

### 5. NV 空页
占位页要放什么:方向说明 + 规划中的数据源清单即可?

## 交接要点(实现侧已知事实)

- 架构:静态站(templates+sitegen)+serve.py(防护/账号/看门狗)+PIAgent 助手;新方向=registry 配置+源模块+模板复用,模型榜(SuperCLUE 链路)是参照实现。
- 数据通道实测:`skills/model-eval`(AA 需 key、LMArena 断连、SuperCLUE PDF 链路可用);**NV 数据源未探测**,立项前先 spike。
- 收录甄别落地为:registry 产品清单加"入榜审核"字段/流程(待口径定了设计)。
- 新功能一律:AGENTS.md 专家流程 → PLAN.md 排期 → 实现 → 沉淀回专家。
