# 产品调研展示（product-showcase）

首个落地：`reports/agentcore-platforms/`（四段式汇报：产品 A → 产品 B → 对比 → 架构提炼，2026-10-12 改版）。
本技能记录五个可复制规则——**汇报组织、文档映射、图示表达、来源保留、更新同步**。

## 0. 汇报组织（先定故事线）

- 展示页是**汇报**不是文档转载：先立故事线（如"A=统一组织 / B=可组合运行 → 对比三个分水岭 → 提炼核心能力检查表"），章节、要点、图都为这条线服务；
- 每章结构：`lead`（一句导语）→ `points`（要点卡）→ 小节（导入/图/步骤）；要点卡 `kind` 必标（fact/judgment/plain），事实类要点必须能通过 ★ 锚点跳回原文段落；
- 研究阶段内容（待验证事项、复核记录、指纹元信息）不进展示页；口径边界放讲稿一句话带过；
- 去掉页头一切非标题信息；导航用侧边粘性目录（scrollspy），章节来源链接沉到小节底部细行。

## 职责边界（先记住）

- **InferTechNote = 研究内容唯一来源**；本代码仓只做呈现。展示侧**不修改**源文档。
- 内容在**构建时导入**（`collector/showcase.py` 读 `data/knowledge-repo/`），
  不在网站侧另写文案；页面不是独立调研，不补充未经原文证实的结论。
- 发现内容问题 → 记录到 `reports/{slug}/content-issues.md`（文件位置/问题/建议），
  交回研究侧；修订后经知识库同步 + 建站自动反映。
- 可基于源文档做**网络检索**核实，但新证据必须回到研究侧落文档后才进展示。

## 1. 文档映射（showcase.yaml）

- 报告目录 `reports/{slug}/` 含 `showcase.yaml` 即被识别为「展示」类型（无需 `file:`）。
- `docs:` 注册全部源文档（key → 知识库相对路径）；章节用 `from: <key>` 引用，
  一份展示可跨多文档聚合（产品文档 + comparison + ……）。
- `chapters:` 汇报章节树；小节按**标题文本**匹配源文档（`##`/`###`，引号/空格差异自动归一化）：
  - `mode: flow` → **图 + 步骤同屏合并卡**（点步骤高亮同图节点、点节点看说明，三者闭环）；
  - `mode: diagram` → 纯交互图（原文 Mermaid 由交互图承载）；
  - `table_filter: [关键词]` → 对比表按首列关键词收窄行（多产品对比只留目标产品）；
  - `compact: true` → 去首行引导句（已由图/上文承载时）；
  - `mode: fold` / `sources_folds` → 折叠块与折叠来源表；
  - `auxiliary: true` → 辅助小节（模式与边界），视觉降级、不抢主线。
- **文档改标题时**：构建日志输出警告，页面该小节显示"文档已变更"提示——这是特性，
  不要吞掉；按警告更新 yaml 的 `heading` 即可。
- 组件说明 `desc_key` 引用源文档表格行（`desc_table_from` + `desc_table_header` 指定表，
  构建时提取、单一来源）；表里没有的视图形节点用 `desc_note`（页面标注"非文档原文结论"）。
- `overview.points` 开篇概览与章 `points` 要点卡：呈现层提炼，`kind` 必填，
  `anchor: doc_key#标题` 生成 ★ 原文锚点。
- **流程卡（默认形态）**：每个产品一张 `mode: flow` 卡——系统关系图 + 核心流程步骤
  **在同一个卡片内**（图与步骤同屏、全屏一起进）；同一产品的图不得在别处再次出现。
  步骤由文档「一次请求如何执行」自动抽取，`step_highlights` 做步骤↔节点联动，
  `steps_note` 声明来源口径。
- `arch_overview`（可选）：跨产品合并图 + yaml 书写步骤（每步 `alibaba`/`amazon`/
  `text` + `highlights`）——仅在需要一页并列对照时使用；默认不用（用户偏好按产品分开）。
- 图中组件说明支持组件级 `table:` 覆盖来源文档、`desc_key` 传列表（多行说明合并）。

## 2. 图示表达（diagram.svg + 交互）

- 交互图是**呈现层研究视图**：必须与文档研究视图（Mermaid）语义一致；图注明确
  "依据公开职责重构，不表示厂商内部结构"。文档改动图结构时同步改 SVG（同步规则 4）。
- SVG 约定：节点 `<g class="sc-node" data-node="id">`，容器用 `sc-container`，
  治理类旁挂 `sc-side`；颜色只用 CSS 变量（随明暗主题）；不写内联色值。
- 交互（每张图独立实例、同屏闭环）：滚轮/按钮缩放、拖拽平移、点击/回车 → 组件说明面板；
  `mode: flow` 的图与执行步骤同一卡片（左图右步骤），点步骤高亮同图节点、点节点看说明，
  图与整页两级全屏。**交互服务于理解，不加装饰动画**。
- 图的数量克制：**每个产品一张流程卡**（图+步骤一体，承载该产品全部流程跳转）+
  一张**提炼层模型图**（如核心能力 7 层，静态层次、不参与流程切换）通常足够；
  同一产品的图绝不在两处重复出现。提炼层图把两产品对应物以小字标注在层上。
- **全屏演示要可用**：⛶ 全屏的是整个流程卡（含步骤与组件面板），全屏内 ←/→、
  数字键切步、Esc 退出——"全屏后没法展示流程"是不可接受的回归。
- 长文本节点用 `<tspan>` 或拆行；中文 13.5px、副文案 11.5px（与站点令牌一致）。

## 3. 来源保留（不得省略）

- 证据基线（日期、复核记录、未实测声明）必须出现在页头，来自 `showcase.yaml →
  baseline`，措辞沿用文档。
- 章节内引用链接按规则重写：库内文档 → `/knowledge/notes/...`；库外路径（如
  `.agents/`）→ GitHub **版本固定**链接（commit 取自构建时的知识库快照）；
  外部来源原样保留。
- 页脚固定提供：摘要/详细文档（知识库）、GitHub 原文（固定 commit）、产品对照。
- **附件**（原始演示文稿等）：以 `attachments:` 注册（label/file/note），下载条渲染在
  报告摘要之后；`note` 必须写版本口径（如"早期版本，结论以修订文档为准"），
  避免旧版材料被当成现行结论。
- 研究判断样式化区分（段首整段 `mark-judgment`；段中 `mark-judgment-inline`），
  待验证事项区独立边框——**样式只标注，不改文案**。

## 4. 更新同步（构建期闭环）

- 数据流：研究侧改文档 → push → 知识库「⟳ 同步知识库」按钮/`sync_knowledge.py`
  → 建站 → 展示页自动导入新内容。无需人工改展示。
- 讲稿（`notes.md`）与演示页同源：改章节或口播内容时两处一起更新；讲稿页地址
  `/notes/{slug}`（登录可见），不放入公开导航。
- 巡检清单（定期或接到报告时）：
  1. 构建日志有无 `[reports]` 展示警告（缺章节/缺组件表行/缺 SVG）；
  2. 指纹是否随最近一次知识库同步变化（未变=未同步或文档未改）；
  3. 源文档章节结构是否变动（新增子节想纳入 → 更新 yaml sections）；
  4. `content-issues.md` 的条目是否已被研究侧修订（修订后从文件移除）。

## 新增下一个产品（如阿里云）的步骤

1. 阅读该产品 summary/detail，确定主线章节（定位 → 架构 → 执行路径 → 设计取舍
   → 辅助 → 研究状态），据此写 `sections`；保留"事实/判断/待验证"的原文分层；
2. 按文档 Mermaid 研究视图重画 `diagram.svg`，组件表行键填 `desc_key`；
3. 同一 `showcase.yaml` 的 `products` 中把该产品提为 `status: ready`（或按对比
   结构拆两个 section 组）；对比章节用 `comparison.md` 作为 `detail_doc` 来源；
4. 走一遍巡检清单后提交；内容问题记入 `content-issues.md`。
